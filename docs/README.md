# Documentation

Start with the [recorded demo](../README.md#get-started), then follow the relevant path:

| Task | Guide |
| --- | --- |
| Define a policy or configure a live run | [B interfaces and migration](iteration-b-migration.md) |
| Choose an example format | [Current PolicyPack and legacy examples](../examples/README.md) |
| Understand versions and the workbench preview | [Project status](project-status.md) |
| Inspect engineering checks | [B maintenance acceptance — 0.3.0a2](iteration-b-acceptance.md), [A acceptance](iteration-a-acceptance.md) |
| Contribute or reproduce a defect | [Contributor guide](../CONTRIBUTING.md) |
| Follow outstanding review findings | [Original F ledger](review-findings.csv) |

The B acceptance record documents the current `0.3.0a2` maintenance verification
and retains the withdrawn `0.3.0a1` results in a separate historical section. See
[project status](project-status.md) for release and preview versions. Historical
results are not a replacement for verification against the current gate.

[C review contracts](https://github.com/dengxianghua888-ops/preference-lab/blob/codex/iteration-c/docs/iteration-c-migration.md)
and [first-user instructions](https://github.com/dengxianghua888-ops/preference-lab/blob/codex/iteration-c/docs/first-user-acceptance.md)
are maintained on the preview branch. They are not default-branch commands.

`demo_report.html` is a retained historical A fixture, not a current run or a hosted
interactive demo. Use the run inspector for current data; review-aware report
commands belong to the C preview.
