## 0.2.1a1 — Iteration A Alpha

Deterministic engineering acceptance is recorded in [iteration-a-acceptance.md](docs/iteration-a-acceptance.md). The GitHub pre-release contains commit-bound publication evidence; this is not evidence of model-quality improvement.

- Construct preference pairs after optional review of the final judgment; retain explicit review outcomes and failures. Original-content evidence verification remains follow-up work.
- Track stage counts and terminal statuses; expose distinct CLI exit codes for completed, partial failure, failure, cancellation and argument errors.
- Load the single authoritative rule handbook from package resources. Document the source-checkout dashboard entry point.
- Separate decision severity from pair-quality heuristics. Stop interpreting stricter decisions as better quality or synthesis trends as training improvement/convergence.
- Separate demo, live and mock outputs and persist provenance. Preserve unknown historical origins.
- Bind generated items to locally assigned request IDs and generation targets; validate supported execution policy settings before model calls.
- Replace unsupported price, label-quality and automatic-improvement claims with explicit Alpha boundaries. The quickstart runs recorded fixtures by default.

F08 and F09 are only partially addressed in this iteration: policy identity/scope and review failure handling. General PolicyPack execution and final semantic validation remain follow-up work. See [migration](docs/iteration-a-migration.md) and the [original finding IDs](docs/review-findings.csv).
